== DESIGN DIGEST ==

Why coherence is load-bearing here (not in GHC): bsc's associated type
functions reduce THROUGH instance selection with no coercion layer, so
an incoherent selection changes bit widths — coherence is type
soundness, not just predictability.  GHC-style fundeps are
improvement-only; bsc's are semantic.

1. Ordered-clause fundep semantics (#1035).  The instances of a
   coherent class form ordered clauses of a type-level function keyed
   on the fundep INPUT positions.  Selection is input-driven: first
   instance whose inputs match is the selected clause; a determined-
   position conflict makes the constraint unsatisfiable as stated
   (T0159, names constraint and selected instance side by side).
   Outputs never bar a match.  `incoherent` classes (and the
   -legacy-defer-instances hatch) keep relational fall-through; their
   matches are MARKED so they are never treated as coherent evidence.

2. Commitment (#1035).  Once no earlier instance could still capture
   the predicate and no in-scope given could discharge it whole, a
   coherent partial reduction COMMITS (bindings, substitution,
   residual subgoals kept) instead of being discarded and re-derived.
   Types: data Commitment = Committable | Provisional; records
   SatResult/SolveResult/Reduction/InstMatch replace the old tuples.
   Residual subgoals carry reduction ancestry; errors report the
   root-most user-meaningful ancestor with accumulated positions.

3. Modal vs actual judgment (#1035/#1037; the load-bearing principle).
   "Could this instance/given ever match after refinement?" must be
   judged with the UNGUARDED unifier (bound set []), because
   refinement includes call-site instantiation of rigid variables.
   Sites: earlierInstanceMayCapture (walk + reducibility probe), the
   committable gate's given-escape check, the pool-reuse guard.
   Judging these guarded turns "not yet" into "never" and yields
   false coherence (pinned by instances/commit/ModalCapture).

4. Bound-variable discipline (#1037).  mgu refuses to substitute a
   bound (rigid) type variable with structure at value kinds; an
   improvement meeting a rigid variable must become an equality
   constraint, never a substitution (stage-1 approximation: DEFER).
   The unified result type gains an arm:
     data Match a = NoMatch | Defer | Conflict | Match a
   Defer = determined positions fail to unify only because of the
   guard (guarded mgu fails, unguarded succeeds) — neither match nor
   conflict yet; retry when refined.  firstMatch ranks
   Match > Conflict > Defer > NoMatch.  Key equivalence: a Defer row
   implies the whole head unifies unguarded, so the walk treats Defer
   as "may capture" (accumulator true) — provably the same behavior
   as the pre-refactor code.  T0161 rejects skolem escapes at
   generalization.  extSubst is the single global-substitution add
   path; -check-subst-bound arms an invariant check there.

5. Numeric settlement (#1036).  The satisfy loop's terminals never
   consult the SAT solver; a solver verdict may reject the program
   but never rewinds a binding or backs a match out (monotonicity is
   structural, not positional).  Residuals stream to their OWNER:
   tiExpl''' settles a definition's retained+deferred residuals in
   ONE solver session (batchSolveNumericPreds); exported
   satisfy/satisfyFV stay verdict-complete, satisfyStream/
   satisfyFVStream serve callers owning a later settlement point;
   two verdict sites settle locally (incoherent-match full-vs-partial,
   tryDefault candidate validation).  Ground verdicts cache
   bidirectionally (tsNumProven/tsNumRefuted) — sound because closed
   arithmetic is context-free; non-ground queries are never cached.
   Measured: FloatingPoint[.]bsv 501 -> 24 sessions, −26% wall clock.
   Carries the b675 ICE fix: deferred numeric-equality dictionary ids
   recorded as semantic bind deps (SolvedBinds[.]addBindDeps).

6. Solved-dictionary pool (#1038).  Two layers: an intra-pass
   "solved" list threaded through sat/satMany (adoption follows the
   bindings — a branch that discards a reduction's SolvedBinds also
   discards its solved entries), and a cross-pass pool in TI state
   deposited by propagateFunDeps under a CLOSED certificate (no free
   unification vars; no stuck type-function applications — a raw-form
   derivation must not discharge the expTConPred-expanded stronger
   goal).  Pool entries must be pure instance derivations: closures
   through givens or through markIncoherent'd bindings are refused.
   Non-ground entries are frame-local (generalization hazard); open
   predicates KEEP FLOWING even when their derivation is pooled
   (dropping them starves metavariable improvement).  A solved
   dictionary never blocks commitment (it is instance evidence and
   cannot contradict the instance choice) — unlike a given.
   DISAMBIGUATION: this is the TYPECHECKER-side pool.  The LiftDicts
   dictPool covered in "KB: bsc artifact graph" (ground IType-keyed,
   elaboration-side) is a different mechanism; do not conflate.

7. Diagnostics principles (in #1035's diagnostics commit).  Rooted
   reports carry the residual's accumulated positions; synthesis-
   failure reports fall back to the predicate's carried positions
   instead of "Unknown position"; the "could also be deduced from"
   hint reduces self-contained (no givens) so its members never
   reference variables the message doesn't define; fail-fast probes
   in generated code defer to the definition-level report (which
   knows the definition's name) when positionless.

8. Test methodology.  Numeric-settle pins are certified solver-only
   by DUAL VARIANTS: the obligation is cross-class entailment
   (Mul#(a,2,b) |- Add#(a,a,b)) that no direct instance or commuted
   given discharges, so each test fails under -no-use-proviso-sat and
   passes with it.  Full-suite baseline: exactly 3 permanent failures
   when run as root (b1595 ccomp, driver/imports UnreadableTop,
   preprocessor DupInclude).  Hygiene: scrub untracked testsuite
   artifacts before every run (stale [.]bo files make bsc -u skip
   recompiles and poison compare_file/warning-count tests), and run
   with the install that matches the tree (a mismatched run-suite
   wrapper invalidates the whole run — this happened; the failure
   signature was "every pin needing the new semantics fails").
